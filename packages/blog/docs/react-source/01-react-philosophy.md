​Fiber 架构的核心目标：优化渲染与交互​​

React 的 Fiber 架构（从 React 16 开始引入）通过以下机制直接优化了性能指标：

- ​​可中断的渲染任务​​：将渲染过程拆分为多个小任务（Fiber 节点），允许高优先级任务（如用户交互）打断低优先级任务（如后台数据加载），从而减少主线程阻塞，提升 ​​INP（Interaction to Next Paint）​​ 指标。
- ​​时间切片（Time Slicing）​​：将渲染工作分摊到多帧中执行，避免长时间占用主线程，确保页面流畅（60 FPS），间接优化 ​​LCP（减少主线程阻塞）​​ 和 ​​CLS（减少布局抖动）​​。
- ​​双缓冲机制​​：在内存中预计算更新，再一次性提交到 DOM，减少不必要的重排/重绘，提升渲染效率。

​​Fiber 如何解决传统架构的瓶颈​​

​​旧架构问题​​：同步递归渲染会导致主线程长时间被占用，用户交互延迟（高 FID/INP），且无法应对复杂组件树的性能需求。

​​Fiber 的改进​​：

- ​​优先级调度​​：用户交互（如点击）被赋予最高优先级，确保即时响应（优化 INP）。

- ​​增量渲染​​：分批次处理组件更新，避免一次性渲染大量内容导致的卡顿（优化 LCP）。

- ​​副作用批量处理​​：减少 DOM 操作次数，降低布局偏移风险（优化 CLS）。

​​React 优化迭代的其他方向​​
除了 Fiber，React 的持续优化还包括：

- ​​并发模式（Concurrent Mode）​​：进一步利用 Fiber 的异步特性，支持更复杂的交互场景（如 Suspense 懒加载），优化 ​​LCP​​ 和 ​​INP​​。
- ​​服务器组件（Server Components）​​：减少客户端 JavaScript 体积，加速首屏渲染（直接提升 LCP）。
- ​​Hooks 优化​​：如 useMemo/useCallback减少不必要的重新渲染，降低主线程负载（优化 INP）。
