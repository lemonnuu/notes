# 浏览器架构

## 进程

- 进程：计算机正在运行的一个程序实例。每个进程都有自己的内存空间、系统资源（如文件描述符、I/O 等），以及一个或多个线程
- 线程：线程是进程中的执行单元，是操作系统调度的最小单位。在一个进程中可以有多个线程，它们共享进程的资源，但拥有各自的执行流。线程是进程的一部分，同一个进程中的多个线程可以并发执行，共享进程的地址空间和系统资源

进程具有独立性，所有的进程相互隔离，独立运行。一个进程的崩溃不会影响其他的进程。进程和进程之间的通信，是通过 进程间通信（IPC，Inter Process Communication） 来进行数据交换和协作的。

一个进程包含多个线程，每个线程并行执行不同的任务。其中一个线程崩溃了，那么整个进程也就崩溃了。线程之间可以相互通信。

> 一个进程可以包含多个线程，每个线程并行执行不同的任务，如果线程间访问的资源是共享的，也可以并发执行

### 并发和并行

- 并发：并发是指多个任务在 同一时间段 交替 执行，从外部看似乎是同时执行的（访问了共享资源）
- 并行：并行是多个任务在 同一时刻 同时执行（访问的资源互不干涉）

### 进程间的通信（IPC）

进程间的通信方式有以下 7 种：

1. 管道（Pipe）：管道是一种半双工的通信方式，它在父进程和子进程之间创建一个共享的文件描述符，通过文件描述符进行通信。管道可以分为匿名管道和命名管道
2. 消息队列（Message Queue）：内核维护的链表结构，进程通过唯一标识（队列 ID） 发送/接收消息
3. 共享内存（Shared Memory）：共享内存运行多个进程访问同一块物理内存区域，进程可以直接读写共享内存中的数据。共享内存是一种高效的 IPC 方式，但需要额外的同步机制来确保数据的一致性
4. 信号量（Semaphore）：信号量是一种用于进程同步的机制，它可以用来控制对共享资源的访问。信号量可以解决临界区问题，确保多个进程按照一定的顺序访问共享资源
5. 套接字（Socket）：套接字是一种网络编程中常用的通信方式，它可以在同一台主机上的不同进程间进行通信，也可以在网络上的不同主机上的进程间进行通信
6. 文件映射（File Mapping）：文件映射允许多个进程共享同一文件的内存映射区域，可以通过对这个内存区域的读写来进行进程间的通信
7. 信号（Signal）：信号是一种软件中断，用于通知进程发生了某个事件。进程可以通过注册信号处理函数来捕获和处理信号

## 浏览器多进程架构设计

现代浏览器采用的都是 **多进程架构设计**，每个标签页通常对应一个 **主渲染进程**，但实际会涉及多个协作进程共同完成页面加载和渲染。以 Chrome 为例，打开一个普通标签页时，至少会分配 4 个进程：

- 核心进程：渲染进程，每个标签页默认 **独立分配** 一个渲染进程，负责解析 HTML/CSS、执行 JavaScript、构建 DOM 树以及页面渲染
- 共享进程：标签页还会依赖浏览器 **全局共享** 的进程，包括：
  - 浏览器主进程：管理标签页生命周期、用户界面及协调其他进程
  - 网络进程：处理所有网络请求（HTTP/HTTPS、DNS 解析等）
  - GPU 进程：负责图形绘制加速，提高渲染性能

除此之外，若标签页使用插件（如 PDF 阅读器），还会有对应的插件进程，按需创建。

:::warning

其中，渲染进程和网络进程是前端工程师需要特别关注的两个进程。

:::

## 渲染进程

浏览器渲染进程包含多类线程，各线程分工协作完成页面渲染、脚本执行、事件处理等任务。以下是主要线程分类及功能概述：

![浏览器进程](/browser/browser-process.svg)

- GUI 渲染线程：负责渲染浏览器界面，解析 HTML、CSS，构建 DOM 树和 Render Object 树，布局和绘制等。当页面触发重绘、回流时该线程也会执行
- JS 引擎线程：JS 引擎线程（如 V8 引擎）负责解析 JavaScript 脚本，运行代码。俗称的 JS 是单线程的就是指的它
- 事件触发线程：管理事件循环，将异步事件（如用户点击、AJAX 回调、定时器到期）的回调函数加入任务队列，等待 JS 引擎处理
- 定时器触发线程：独立处理 setTimeout 和 setInterval 的 计时 任务，避免 JS 单线程计时不准确问题。计时完成后，回调函数通过事件触发线程加入任务队列
- 异步 HTTP 请求线程：处理 XMLHttpRequest 或 Fetch 等网络请求，与浏览器的网络进程协作。请求完成后，回调函数通过事件触发线程加入任务队列
- 合成线程：负责将页面的不同渲染层进行合成，与 GPU 进程协作加速图形渲染，处理滚动、动画等高性能需求

实际上，渲染进程并非仅有这些线程，还有布局线程、栅格线程等。只不过上述的线程是最值得关注的！

:::danger
由于 GUI 渲染线程和 JS 引擎线程都需要访问和操作 DOM，所以做了线程安全的处理。即 **GUI 渲染线程和 JS 引擎线程是互斥的**，当 JS 引擎执行时 GUI 线程会被挂起，GUI 更新会被保存在一个队列中等到 JS 引擎空闲时被立即执行。这种机制解释了以下现象：

- JS 文件会阻塞页面加载，通常建议放在 HTML 底部，若 JS 文件放在 HTML 头部，解析和执行会延迟页面首次绘制（FP）
- 为了解决长任务（如 React 老版本的组件递归更新）导致的页面卡顿，React Fiber 架构引入了时间切片，将同步渲染拆分为可中断的异步任务，避免 JS 线程长时间独占主线程，提升交互响应速度

:::

### 浏览器内核与 JS 引擎

在工作生活中，我们常把浏览器分为 “浏览器内核” 和 “JS引擎”，两者协同工作，在架构上分属不同的模块。这种分离设计提高了浏览器的模块化和性能优化空间。

- 浏览器内核：也称为渲染引擎或排版引擎，主要负责解析 HTML、CSS 并渲染为用户可视化页面。它决定了浏览器如何显示网页内容、处理交互逻辑以及兼容性表现。GUI 渲染线程就是基于渲染引擎工作的
- JS 引擎：负责解析、编译和执行 JS 代码，其工作职责涵盖 JS 代码从加载到最终执行的完整流程，包括代码解析（Parsing）、即时编译（JIT）、解释执行、内存分配、垃圾回收（GC）、与宿主环境交互等
